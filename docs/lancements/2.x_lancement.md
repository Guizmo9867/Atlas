# Lancement de la phase 2.x — subdivisions de tous les États au 1er janvier 1945 (boucle automatique)

*Fiche de lancement rédigée par Claude le 15/10/2026, pour Ether. Cadre : `00_METHODE_ATLAS_v2.md` (v2.1, précisée le 15/10). Modèle : le pilote 2.FR, intégré le 15/10 (compte rendu `01_lots/2.FR/2026-10-15_claude_compte_rendu_1.md`). Remplace, pour la suite, la fiche `00_LANCEMENT_2.FR.md`.*

## 0. Feu vert et fonctionnement

- **Feu vert de Guizmo : 15/10/2026**, pour toute la phase 2.x, **en boucle automatique**, en commençant par le **groupe 1 : Belgique (`2.BE`), Luxembourg (`2.LU`), Pays-Bas (`2.NL`), Suisse (`2.CH`)**.
- Les groupes suivants (§6) s'ouvrent **après le bilan du groupe 1** (temps, coût, qualité) : Claude l'écrit au tableau de bord et Guizmo dit « on continue ». En attendant, ne pas commencer le groupe 2.
- **Comme pour les villes** : tu livres un lot, puis tu passes **tout de suite** au suivant, sans attendre le compte rendu. Au réveil suivant (toutes les heures, à la 12e minute), Claude intègre et dépose son compte rendu ; tu réponds au compte rendu quand tu veux (cycle 2, cycle 3), en continuant les autres lots. **Au plus 3 cycles par lot** ; ce qui reste va en réserve pour la revue avec Guizmo. Au plus **2 lots en attente de Claude** en même temps.
- Échange inchangé : `01_lots/2.<XX>/`, `STATUT.json`, `PRET_ether.md` en dernier ; Claude répond par `PRET_claude.md`. Questions numérotées `Q2<XX>-01`… ; réserves `R2<XX>-01`….
- Pas de question à Guizmo pendant un lot : ce qui demande sa décision part en réserve (ou, pour une licence de tracé douteuse, Claude le met lui-même « à trancher »).

## 1. Ce qu'on cherche (un lot = un État de 1945)

Le **découpage administratif en vigueur au 01/01/1945 à 0 h** dans **un État** (celui de la souveraineté retenue par l'Atlas pour ses territoires : `souverainete_id` des fiches `territoire-…` déjà intégrées), sur deux échelons :

- **Échelon 1** = le premier niveau sous l'État (provinces, cantons, Länder, voïvodies, républiques fédérées…).
- **Échelon 2** = le niveau en dessous (arrondissements, districts, Kreise, oblasts…), **seulement s'il est utile à l'échelle de l'Atlas** et documentable. Pour un petit État, un seul échelon peut suffire (dis-le).
- Le **mot local** (province, canton, Gau…) va dans `statut_administratif` ; l'échelon est générique, le même sens dans tous les pays.
- **Pas plus fin** (communes, cantons français…).
- **Deux systèmes à la fois** (ex. Reich : Länder et provinces de l'État + Gaue du parti ; pays occupés : découpage de droit + découpage de l'occupant) : on garde la **règle du pilote** — les subdivisions portent le **découpage et la souveraineté de droit** ; le contrôle réel vient des territoires et des fronts déjà sur la carte. Si l'autre système compte vraiment pour les circulations, pose la question (`Q2<XX>-…`) au lieu de l'ajouter.
- Le **découpage de 2026 ne sert pas** de modèle : on cherche celui de 1945. Les 61 zones de 2026 servent seulement à vérifier, à la fin de la phase, qu'aucune partie de la carte n'est oubliée.

## 2. Les fiches (même format que 2.FR)

| Champ | Contenu |
|---|---|
| `entite_id` | `subdivision-<code du pays ACTUEL où elle se trouve surtout>-<nom actuel sans accents>` (ex. `subdivision-be-anvers`, `subdivision-ch-geneve`). Une circonscription nommée d'après sa ville : `subdivision-<cc>-<type>-<ville>` comme `subdivision-fr-commissariat-lyon`. |
| `nom` (fiche) | le nom usuel **en français** s'il existe (Anvers, Grisons), sinon le nom local |
| `nom_court` (fiche) | le nom **court affiché sur la carte** (ex. « Anvers », « Région de Lyon ») |
| `etats[0].proprietes.nom` | le **nom officiel au 01/01/1945**, dans la langue de l'État (plusieurs langues officielles : la forme la plus courante dans la source, les autres dans `autres_noms_hors_date` ou une note) |
| `niveau` (ou `echelon`) | 1 ou 2, au sens ci-dessus |
| `statut_administratif` | le mot local (`province`, `canton`, `district`…) |
| `code` | seulement s'il est attesté à la date |
| `parent_id` | la subdivision d'échelon 1, ou le territoire de l'État (`territoire-be-belgique`…) |
| `souverainete_id` | celle de droit au 01/01/1945, avec une note si le contrôle réel diffère |
| `chef_lieu_propose` | `{nom, annee_preuve, source_id, locator, statut, ville_id_existante}` : une **référence**, jamais publiée comme chef-lieu 1945 validé sans preuve à la date |
| `sources` | `[{source_id, locator, usage}]`, selon le protocole |
| `valid_from` | `1945-01-01` (début de la fenêtre observée, pas la création) ; `valid_to` inconnu |

Pour les villes : rien à créer. Liste seulement, dans `atlas_2<XX>_pour_claude.md`, les chefs-lieux qui n'ont pas de fiche ville (ils feront un complément de villes plus tard, sur décision de Guizmo).

## 3. Les tracés

- **Licences acceptées par l'outil de Claude** : domaine public, **CC0**, **CC BY** (sans NC, SA ni ND), Licence Ouverte / Etalab, OGL (Royaume-Uni), DL-DE BY ou Zero (Allemagne). **Tout le reste est refusé automatiquement** (et mis « à trancher par Guizmo ») ; **toute donnée OpenStreetMap ou ODbL est interdite**. Écris la licence exactement (ex. `CC BY 4.0`).
- Un tracé douteux mais livré quand même : mets `ne_pas_integrer` dans son `statut` (comme les tracés alpins de 2.FR), avec la réserve. Sinon, **tout tracé à licence acceptée est affiché** (statut provisoire).
- Pas de tracé trouvé : livre la fiche sans tracé (elle n'apparaîtra pas sur la carte, mais elle existe).
- Claude simplifie lui-même (mapshaper, 400 m pour l'échelon 2, 600 m pour l'échelon 1) : livre le tracé à sa résolution d'origine, en longitude/latitude (EPSG:4326).

## 4. Le livrable : noms de fichiers OBLIGATOIRES (l'outil de Claude les cherche)

Dans `01_lots/2.<XX>/` (`<XX>` = BE, LU, NL, CH… ; un grand État coupé en parties : `2.SU-UA`, fichiers `atlas_2SUUA_…`) :

1. `atlas_2<XX>_subdivisions_proposees.json` : `{ "metadata_lot": { "lot", "etat_1945", … }, "entites": [ … ] }` ;
2. `geometries/atlas_2<XX>_geometries_proposees.geojson` : une FeatureCollection ; propriétés de chaque tracé : `geometry_id` = `geom-<entite_id>-1945-01-01`, `entite_id`, `licence`, `attribution`, `statut`, `sources` (liste de `source_id`), `limite`, `operations`, `millesime_source`, `reserves`, `points_a_verifier` (facultatif) ;
3. `atlas_registre_sources_2<XX>_delta.json` : `{ "ajouter": [ … ], "completer": [ … ] }` (format du protocole ; une source déjà au registre va dans `completer`) ;
4. `atlas_2<XX>_pour_claude.md` : réponses, questions, chefs-lieux sans fiche ville, raccords avec les voisins ;
5. `atlas_2<XX>_reserves.md` ;
6. `preuves/` : captures des pages qui prouvent (Claude les lit ; elles restent hors du dépôt public) ;
7. le **temps actif** (début et fin de chaque séquence de travail réel, sans les nuits ni les attentes) dans `STATUT.json` ou le bilan ;
8. `STATUT.json`, puis **en dernier** `PRET_ether.md`.

**À chaque nouveau cycle, relivre les fichiers 1 à 3 complets** (pas seulement les changements) : l'outil remplace le lot entier.

## 5. Ce que fait Claude à chaque livraison (pour info)

Lecture des sources et des captures → outil `outils/subdivisions/integrer_subdivisions.py` (contrôles, licences, simplification, fusion des sources) → validateur sans erreur → envoi sur GitHub (la carte en ligne se met à jour) → compte rendu `01_lots/2.<XX>/<date>_claude_compte_rendu_<n>.md` → `PRET_claude.md`. Une erreur bloquante (ID invalide, parent ou source introuvable) n'intègre rien : le compte rendu donne la liste, et ça compte comme un cycle.
